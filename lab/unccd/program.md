# Artemis Project 1: independent reproduction of UN-CCDs

**Paper.** Rui Shi, Elvan Ceyhan and Nedret Billor, "Clustering with Uniformity- and
Neighbor-Based Random Geometric Graphs", arXiv:2501.06268v3 (14 April 2026).

**Code.** The authors' public repository,
github.com/Rui-Shi/Cluster-Catch-Digraphs-for-Clustering-and-Outlier-Detection, pinned at
commit 9bc803219933be17e28ccc0af703844ebf97ea5a. It has no licence file, so it is cloned
into `lab/unccd/vendor/` by `prepare_data.py` and never committed here. Every file the
reproduction reads is fingerprinted in `data/snapshot.json`; the harness stops if any
fingerprint changes.

**Role.** This is the replication arm of Artemis. No agent edits code and there is no
mutable experiment file. The question is whether the published numbers come out of the
published code, and how much they move with the row order of the data, the random seed
and the Monte Carlo null table.

## What is fixed before any result is seen

1. **Method code.** The authors' functions are sourced unchanged. The paper's Algorithm 4
   is `UNCCD_clustering` in `methods/clustering/UN-CCDs.R`.
2. **Null tables.** The authors' null tables for these dimensions are not in their
   repository. `null_tables.py` builds them with 10,000 Monte Carlo iterations, using the
   first k points of one uniform sample as the sample of size k. It was checked against
   the authors' own generator (`R/ccds/quantile_table.R`) at d = 2 and d = 10, n = 40,
   4,000 iterations each: the standardised differences have mean near 0 and standard
   deviation near 1 at all six levels (`docs/results/unccd_repro1/null_table_validation_d*.json`).
   Seeds: 20261014 + d.
3. **Data.** Real data come from the authors' loader `data/clustering/Real_Data_Collection.R`,
   evaluated with only the `setwd` to a missing folder and two unused `library` calls
   removed. Simulated data are regenerated by evaluating the authors' driver scripts in
   their own random-number stream (`set.seed(2024)`, then the 2-, 3- and 5-cluster lists in
   order) with the parallel clustering call replaced by a capture of `data_list`. Repetition
   r of a cell is therefore the authors' repetition r.
4. **Row permutations.** Original order (perm 0) plus 100 shuffles with seeds 1001 to 1100.
5. **Baseline seeds.** DBSCAN is deterministic and runs once. K-means++, spectral
   clustering and Louvain run with seeds 1 to 100. Their settings are read from the
   authors' scripts. ClusterR is not installable here, so K-means++ uses k-means++ seeding
   followed by Lloyd iterations (`kmeanspp()` in `r/unccd_job.R`), which is what
   `KMeans_rcpp(..., initializer = "kmeans++")` does with one start.

## Three readings of the UN-CCD real-data protocol

* **driver**: the settings in the authors' real-data driver
  (`simulations/clustering/UN_CCDs/Simulations/Real_Data/Real_Data_UNCCD.R`): a quantile
  level and a scan direction chosen per dataset, and the null table for the dimension named
  in the table file.
* **stated**: the protocol as the paper states it (Section 5): alpha = 1% for every
  dataset, the ascending scan of Algorithm 4, and the null table for the data's dimension.
* **driver_dfix**: the driver's settings with the null table for the data's actual
  dimension, run only where the two dimensions differ (user knowledge and wholesale).

## Pre-registered criteria

* **C1 (real data, reproduction).** Under the driver reading, in the original row order, a
  published UN-CCD result is *reproduced* if ARI is within 0.01 and the number of clusters
  matches; *approximately reproduced* if ARI is within 0.05; otherwise *not reproduced*.
* **C2 (row order).** A result is *order-sensitive* if, over the 100 shuffles, the
  5%-to-95% range of ARI is wider than 0.02 or the number of clusters differs from the
  original-order result in more than 5% of shuffles.
* **C3 (stated protocol).** Report the stated-protocol results beside the published ones;
  no pass mark, since the question is descriptive.
* **C4 (baselines).** A published baseline value is *consistent* if it lies within the
  range of the 100 seeded runs (or equals the single DBSCAN run to three decimals), and
  its percentile within the seeded runs is reported.
* **C5 (simulations).** For each piloted cell, the published mean ARI is *reproduced* if it
  lies inside the bootstrap 95% interval of our mean over the same repetitions, or within
  0.02 of our mean.
* **C6 (code and text).** Every difference noticed between the paper's description and the
  code is listed with file and line, without judging intent.

## Scope on this machine

The workspace has two CPU cores. Real data run in full. Simulation cells are piloted on
the authors' first repetitions; `modal_sweep.py` runs the full 500 repetitions per cell on
Modal under the user's account.

## Changes made during the run (recorded as they happened)

* **Compute caps.** One UN-CCD run on D31 (n = 3,100) took 7 to 18 minutes here and one
  spectral run on D31 about 45 minutes. D31 therefore gets 5 shuffles per reading instead
  of 100, spectral clustering 3 seeds on D31 and 50 on asymmetric, and Louvain 5 seeds on
  D31. The D31 cap was lowered in steps (20, then 10, then 5) after the first two D31 UN-CCD
  results and the first spectral D31 run were in; the caps were set by run time, not by
  the values.
* **Simulation pilot.** Full 500 repetitions for the Uniform d = 2, n = 50 and Gaussian
  d = 2, n = 50 cells and for the three Uniform d = 20, n = 200 cells; the first 200
  repetitions for Gaussian d = 20, n = 200 (5 clusters), Gaussian d = 10, n = 200 (3
  clusters) and Uniform d = 10, n = 200 (3 clusters); the first 20 for the three Uniform
  d = 5, n = 500 cells (a timing check).
* **Second null table.** An independent table with a different seed (tag B) for every
  dimension the real-data driver names and for d = 20, to measure how much results move
  with Monte Carlo noise in the table.
* **Post hoc diagnostics (not part of the pre-registered criteria).** After the Uniform
  d = 20, n = 200, 5-cluster cell failed C5, its first 100 repetitions were rerun with the
  ascending scan, and with the quantile level 99 (alpha 1%) instead of 99.9, to look for
  the setting behind the published value.
